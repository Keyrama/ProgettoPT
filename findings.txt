4. KEY SOURCE SNIPPETS (retrieved via the LFI, php://filter base64)
-------------------------------------------------------------------------------
view.php:
    <?php include $_GET['file']; ?>        // no sanitization, no auth check

config.php:
    DB_SERVER=127.0.0.1  DB_USERNAME=admin  DB_PASSWORD=adminpass  DB_NAME=impsdb

login.php (vulnerable query):
    $sql = "SELECT id, username FROM users
            WHERE username = '".$username."' AND password = '".md5($password)."';";
    // username concatenated raw -> SQLi. Logs in when num_rows == 1.
    // Bug: $_SESSION["id"] = $id;  but $id is never fetched -> undefined (Warning).
    // Double session_start() -> headers-already-sent -> first login redirect fails.

register.php (vulnerable + info leak):
    $sql = "SELECT id, username, password FROM users WHERE username = '".$_POST["username"]."';";
    if ($result->num_rows > 1) { echo "...DEBUG INFO: ".$sql; }   // prints full query
    $sql = "INSERT INTO users (username,password) VALUES ('".$username."','".md5($password)."');";

upload.php / open.php:
    Static HTML forms only. No $_FILES, no move_uploaded_file anywhere.
    => "file upload" feature does NOT actually process uploads. Not exploitable.

6. PHP CONFIG WEAKNESSES (from info.php - support the findings above)
-------------------------------------------------------------------------------
  disable_functions      = (empty)   -> system/exec/shell_exec all enabled -> LFI becomes RCE
  open_basedir           = (empty)   -> LFI can read ANY file on the filesystem
  display_errors         = On        -> verbose errors leak paths/line numbers/vars
  expose_php             = On        -> X-Powered-By header
  allow_url_include      = Off        -> no classic RFI (use php://filter chain instead)
  allow_url_fopen        = On        -> php://filter / data wrappers available for read
  session.cookie_httponly= Off
  session.cookie_secure  = Off
  session.use_strict_mode= Off        -> session fixation possible
